# 文案模板使用说明

`script.example.json` 是跑通并验收过的真实结构，复制到 `work/script.json` 后改写。
格式契约见 `schemas/script.schema.json`。

## 硬约束

| 项 | 要求 | 原因 |
|---|---|---|
| 句数 | 22 – 30 句 | 对应 40–55 秒成片 |
| 单句字数 | 6 – 12 字 | 一句话一个镜头，超了字幕会折行 |
| 总时长 | 40 – 55 秒 | 抖音带货片的有效注意力区间 |
| 钩子 | 前 3 句内出现 | 决定完播率 |
| 语速 | `voice.speed` 1.2 – 1.4 | 低于 1.2 节奏拖，高于 1.4 听不清 |

## 写文案前必须做的两件事

1. **读 `reference/lessons.md`**：里面是历次验收被否掉的原因，避免重犯。
2. **读 `work/material/material-index.json`**：确认每个卖点在素材里有对应画面。
   素材里没有的东西不要写——写了也配不上画面，等于自造矛盾。

## 卖点必须能被画面证明

文案里的每个具体名词，都应该是"画面上能看见的东西"：

| 能写 | 不能写（除非素材真的有） |
|---|---|
| 前扣、肩带、底围、杯垫、浅蓝边 | 上身效果、显瘦、聚拢 |
| 棕色、黑色、豹纹、裸色 | 透气、凉爽、无痕（看不见） |
| 多款、包装袋、走线 | 用了三个月不变形（无法证明） |

判断方法：写完一句，问自己"这句话里有哪个词是画面必须给出证据的"，
拿这个词去 `material-index.json` 里搜，搜不到就改写。

## 结构骨架

```
钩子(1-3) → 反向筛选(4-5) → 产品引入(6) → 功能卖点(7-15) → 颜色(16-20) → 促单(21-26)
```

每句挂一个 `intent`，方便复盘时看哪一段掉链子。

## `shotHint` 怎么填

`flatlay` / `handheld` / `product_closeup` / `model_wear` / `package`。
它只是软提示（加分项），真正决定画面的是语义匹配。填不准不会出错，但填对了能提命中率。
